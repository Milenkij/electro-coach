# Упаковка артефактов: Ильяхов-стиль и PDF-конвейер

**Источник:** практика. Сложилось в сессиях 2026-04-22 и 2026-04-24. Не из книги.

## TL;DR

- Все артефакты канвы (сама канва, SWOT, Strategic Assessment, Recommendations) пишутся в **информационном стиле** Максима Ильяхова: короткие предложения, факты, без воды.
- Финальная выгрузка — **PDF**, чтобы передать клиенту или сохранить в архив.
- Конвейер: md → PDF через `pandoc --pdf-engine=weasyprint`. Кириллица читается без настройки шрифтов на macOS.
- Проверка корректности — `pdftotext`.

---

## Принципы Ильяхов-стиля

| Принцип | Что значит | Антипример → пример |
|---|---|---|
| **Короткие предложения** | Один смысл — одна фраза | «Учитывая вышеизложенное, можно предположить…» → «Скорее всего, X» |
| **Факты вместо оценок** | Цифры и события, не эпитеты | «Огромный дефицит» → «Дефицит -180к ₽/мес» |
| **Без стоп-слов** | Удалить «в рамках», «в целях», «по факту», «касательно», «в свою очередь» | «В рамках работы над канвой» → «Делая канву» |
| **Без modality без нужды** | «Кажется», «возможно», «наверное» — только когда явно про гипотезу | «Кажется, есть проблема» → «Есть проблема» (если факт) |
| **Глаголы вместо отглагольных существительных** | «Решить», не «принятие решения» | «После принятия решения» → «После решения» / «Решив» |
| **Заголовки и списки** | Вместо абзацев | Абзац → список с маркерами |
| **Полезное действие** | Текст помогает читателю что-то сделать | «Текст про текст» → «Сделай X, Y, Z» |
| **Без англицизмов** (по запросу пользователя) | Заменить английские слова на русские | «runrate» → «текущая выручка», «pipeline» → «воронка» |

---

## Когда не пишем в Ильяхов-стиле

- Цитаты пользователя в секции `Evidence` — **verbatim**, без правок (см. `business-model/SKILL.md`).
- Названия книг, фреймворков, продуктов — оставить как есть. «Business Model Canvas» допускается, но «канва» удобнее в тексте.
- Терминология методологии — короткие сокращения блоков (ПС, ЦП, КС и т. д.) допустимы внутри таблиц.

## PDF-конвейер

### Зависимости (macOS)

```bash
brew install pandoc weasyprint
```

### Команда

```bash
cd <путь к md-файлу>
pandoc <input>.md --pdf-engine=weasyprint -o <output>.pdf
```

Кириллица работает «из коробки» — weasyprint берёт системные шрифты macOS.

### Проверка

```bash
pdftotext <output>.pdf - | head -40
pdfinfo <output>.pdf
```

`pdftotext` извлекает текст из PDF. Если кириллица читается — выгрузка корректна.

`pdfinfo` показывает страницы и размер. Для типового SWOT-анализа: 6–8 страниц, 30–60 КБ.

### Куда класть PDF

- **Не коммитить в git.** Это generated-артефакт, легко пересоздаётся из md.
- Хранить локально в `business-model/output/` или передавать клиенту напрямую.
- Добавить `business-model/output/` в `.gitignore`, если ещё не добавлено.

## Шаблон команды для агента

После завершения канвы или SWOT-анализа в md, агент:

1. Подтверждает у пользователя название и путь PDF.
2. Запускает `pandoc --pdf-engine=weasyprint`.
3. Проверяет результат через `pdftotext` (читается ли кириллица).
4. Сообщает путь к PDF и краткие метаданные (страницы, размер).
5. Не коммитит PDF в git.

## Предупреждения weasyprint

При конвертации weasyprint может выдавать предупреждения о CSS-свойствах вроде `text-rendering`, `gap`, `overflow-x`. **Они безвредны** — содержимое PDF корректно. Игнорировать.

## HTML-дашборд (опционально, рядом с PDF)

Кроме PDF можно сгенерировать визуальный HTML-дашборд: канонический вид канвы Остервальдера (5×2 grid) + карта эмпатии + риски + рычаги + 3 шага. Открывается в браузере, печатается через `Cmd+P`.

Шаблон лежит в проекте: `business-model/templates/dashboard.html`.

### Когда использовать

- Когда нужна визуальная канва, а не текстовый md-файл.
- Когда передаём результат человеку, который привык к канонической канве.
- Когда хочется напечатать одним листом A3.

PDF из md остаётся основным форматом. HTML-дашборд — дополнение.

### Как генерируется

В шаблоне есть маркеры `{{NAME}}`, `{{SEGMENTS}}`, `{{SEGMENTS_COLOR}}` и т. п. Агент:

1. Читает финальный md-файл канвы.
2. Берёт шаблон `business-model/templates/dashboard.html`.
3. Подставляет значения в маркеры.
4. Сохраняет результат в `business-model/output/<имя>.html`.

### Цветовая разметка блоков

Цвет рамки определяется итогами SWOT по блоку (см. [04-strategy.md](04-strategy.md), §2):

- 🟢 `green` — сильный блок (S).
- 🟡 `yellow` — есть возможности или вопросы (O).
- 🔴 `red` — слабое место или внешняя угроза (W/T).

Маркер цвета — `{{<BLOCK>_COLOR}}` (например, `{{SEGMENTS_COLOR}}`). Подставляется значение `green`, `yellow` или `red`.

### Маркеры в шаблоне

| Маркер | Откуда брать |
|---|---|
| `{{NAME}}` | Имя проекта |
| `{{VERSION}}`, `{{DATE}}` | Версия и дата |
| `{{ENV_MARKET}}`, `{{ENV_INDUSTRY}}`, `{{ENV_TRENDS}}`, `{{ENV_MACRO}}` | 4 силы среды из [04-strategy.md](04-strategy.md), §1 |
| `{{PARTNERS}}`, `{{ACTIVITIES}}`, `{{RESOURCES}}`, `{{VALUE}}`, `{{RELATIONSHIPS}}`, `{{CHANNELS}}`, `{{SEGMENTS}}`, `{{COSTS}}`, `{{REVENUE}}` | Содержание 9 блоков канвы |
| `{{<BLOCK>_COLOR}}` | Цвет рамки по SWOT для каждого блока |
| `{{EMPATHY_SEGMENT}}`, `{{EMPATHY_SEES}}`, `{{EMPATHY_HEARS}}`, `{{EMPATHY_THINKS}}`, `{{EMPATHY_SAYS}}`, `{{EMPATHY_PAINS}}`, `{{EMPATHY_GAINS}}` | Карта эмпатии главного сегмента (см. [03-design.md](03-design.md)) |
| `{{RISKS}}` | Риски из SWOT, по убыванию остроты. HTML-фрагмент с `<div class="risk-item">…</div>` для каждого риска |
| `{{LEVERS}}` | Гипотезы из 5 стилей + 55 паттернов + 4 действий. HTML-фрагмент с `<div class="lever-item">…</div>` для каждого |
| `{{STEP_1}}`, `{{STEP_2}}`, `{{STEP_3}}` | 3 ближайших шага из стадии 5 |
| `{{CHECKPOINT}}` | Точка проверки из стадии 5 |

### Куда класть

`business-model/output/<имя>.html`. В git **не коммитится** — generated артефакт, легко пересоздаётся из md и шаблона.

`business-model/output/` уже в `.gitignore`.
