## Решение

Каждый ран остаётся на **своей версии пайплайна** навсегда. Delta в методологии → новая версия шаблона (`pipeline-templates/v2/`), не мутация старых ранов.

## Почему

- **Воспроизводимость:** спустя полгода можно сравнить Run 1 (v1) и гипотетический Run 5 (v2) и понять, что поменялось в подходе, а не только в предмете
- **Защита от «лечим в процессе»:** на середине рана нельзя сменить методологию. Это жёсткая дисциплина — зафиксировали план, прошли, зафиксировали результат, потом делаем выводы
- **Learnings становятся дифф-сигналом:** если между v1 и v2 сильно выросло число этапов — значит, методология становится тяжёлой; это повод переосмыслить

## Как создавать новую версию пайплайна

Триггеры (хотя бы один):
- Новая обязательная стадия (как Stage 0 в v1 → будущее)
- Принципиально другой артефакт на выходе одной из стадий
- Переход на другую governing methodology

Рецепт:
```bash
cp -r pipeline-templates/v1 pipeline-templates/v2
# Внести изменения, обновить README и changelog
# Новые раны стартуют от v2; старые остаются на v1
```

## Что НЕ триггер

- Улучшение формулировки промпта — это edit внутри v1
- Новая карточка в `/knowledge/` — это независимое изменение
- Новый паттерн — это независимое изменение

Версионируется **скелет** пайплайна и набор стадий, не содержательные правки.
