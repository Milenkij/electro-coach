# AJTBD Graph — интерактивная визуализация графа работ

Одностраничный дашборд для аналитической работы с графом работ фаундера: 11 работ от Big Job, 27 конкурентных решений, зоны входа/удержания, фильтры по силе и покрытию.

**Источник истины:** [../2-3-MVP B2B/results/ajtbd-analysis.md](../2-3-MVP%20B2B/results/ajtbd-analysis.md) + [../2-3-MVP B2B/results/ajtbd-competitors.md](../2-3-MVP%20B2B/results/ajtbd-competitors.md).

---

## Как открыть

### Локально

Страница тянет `data.json` через `fetch()`, поэтому нужен локальный http-сервер (из `file://` браузер блокирует CORS).

```bash
cd ajtbd-graph
python3 -m http.server 8000
# открыть http://localhost:8000
```

Альтернативы: `npx serve .`, расширение «Live Server» для VSCode.

### На GitHub Pages

После `git push` в `main` страница автоматически публикуется по адресу:
`https://<github-username>.github.io/<repo>/ajtbd-graph/`

Репозиторий настроен на деплой из корня `main` (прецедент — `b2b.html`). Ничего дополнительного настраивать не нужно.

## Структура папки

```
ajtbd-graph/
├── index.html    — UI: two-panel (список работ / деталь), фильтры, ваниль JS
├── data.json     — все данные: Big Job, 11 работ, 27 решений, зоны, легенда
└── README.md     — этот файл
```

**Принцип:** данные отделены от интерфейса. Контент обновляется через `data.json` без правки HTML. UI правится в `index.html` без правки данных.

## Как обновить данные

Отредактируй `data.json`. Схема:

### `meta`
```json
{ "title": "...", "subtitle": "...", "updated": "YYYY-MM-DD", "sources": [...] }
```

### `segment` — одна строка профиля клиента.

### `bigJob` — Big Job фаундера
```json
{
  "title": "...",
  "when": { "context": "...", "trigger": "...", "knowledge": "...", "emotions": "..." },
  "want": "...",
  "criteria": ["...", "..."],
  "soThat": "..."
}
```

### `coreJob` — Core Job продукта
```json
{ "title": "...", "layers": ["...", "..."], "force": 10 }
```

### `zones` — три зоны: `entry`, `retention`, `outside`
```json
{
  "entry": { "key": "entry", "label": "...", "description": "...", "works": ["W5","W6"], "color": "#2d6a4f" }
}
```

### `coverageLegend` — три уровня покрытия: `full`, `partial`, `none`
```json
{
  "full": { "symbol": "★", "label": "...", "description": "...", "color": "#2d6a4f" }
}
```

### `works[]` — массив из 11 работ
```json
{
  "id": "W6",
  "name": "...",
  "force": 10,
  "zone": "entry",
  "coverage": "full",
  "ourRole": "Наша роль на этой работе...",
  "when": { "context": "...", "trigger": "...", "emotions": "..." },
  "want": "...",
  "criteria": ["...", "..."],
  "problems": "...",
  "solutions": [6, 7, 8, 9, 10, 11, 12, 13, 17, 27]
}
```

Важно: `solutions` — массив id из справочника `solutions[]`. Если добавляешь новое решение — сначала добавь в `solutions[]`, потом сошлись на его id из `works[].solutions`.

### `solutions[]` — справочник решений (27 штук)
```json
{
  "id": 27,
  "name": "Наш продукт",
  "brief": "одна строка",
  "detail": "развёрнутое описание, чего не закрывает",
  "type": "us",
  "cost": "150K entry / 300–500K ₽/мес",
  "isUs": true
}
```

`isUs: true` — метит наш продукт (выделяется зелёной рамкой).

### Типичные сценарии правок

- **Добавить работу:** новый объект в `works[]`, укажи id (W12), зону, coverage, force.
- **Добавить решение:** новый объект в `solutions[]`, присвой новый id, сошлись из нужных работ.
- **Перевести работу в другую зону:** поправь `zone` у работы. Поправь массив `zones.<key>.works`.
- **Изменить Core Job:** правь `coreJob.title` и `coreJob.layers`.

## Как изменить интерфейс

Весь UI — в `index.html`:

- **Стили:** CSS-переменные в `:root` — цвета, радиусы, тени. Меняй там, а не в конкретных селекторах.
- **Фильтры:** добавить новый фильтр — добавь UI в `<div class="filters">`, регистрируй в `state.filters`, учитывай в `works()`.
- **Детальная карточка:** функция `renderDetail(w)`. Блоки — это `<section class="block">` с `.block-title`.
- **Карточка работы в списке:** функция `workCard(w)`.
- **Hero/легенда:** функция `renderEmptyDetail()`.

Чтобы видеть изменения без деплоя — обновляй страницу локально через http-сервер.

## Как задеплоить

```bash
git add ajtbd-graph/
git commit -m "ajtbd-graph: update data / UI"
git push origin main
```

GitHub Pages пересобирает сайт автоматически через 30–60 секунд. Проверить — открыть URL страницы и посмотреть `updated` в шапке.

Если страница не обновляется — проверь GitHub Actions в репозитории (вкладка Actions на GitHub).

## Дизайн-решения (зачем так)

- **Вариант «кастомный HTML + vanilla JS»** вместо Markmap / Obsidian — потому что нужен не просто граф, а интерактивная карточка работы с контекстом / ценностями / решениями. Markmap показывает только структуру. Obsidian-плагины привязывают к клиенту.
- **Нет фреймворков** (React/Vue) — чтобы открывалось на чистом html-сервере, без сборки. Вес страницы ≈ 15 KB + data.json.
- **Светлая тема** — потому что это аналитический инструмент, а не презентация для клиента. Dark — для лендингов.
- **Accent #2d6a4f (тёмно-зелёный)** — чтобы выделять наш продукт и не конкурировать с синим-брендовым `#5b8def` на лендингах.
- **Данные в JSON** — быстрый diff в git, легко править без знания HTML, легко генерировать из MD-файлов в будущем.
