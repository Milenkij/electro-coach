# 05 — Оценка системы коммуникаций

Проверить, как команда будет **работать вместе** в ране: регулярные встречи, каналы, решения, конфликты.

**Применимо для рана с командой.** Для dyad — в урезанной форме (только каналы и ритм).

## Вход

- Выполнен `03-team-core-mapping.md`
- Выполнен `04-team-interviews.md` (если есть команда)

## Работа

### 1. Текущие ритуалы

- Какие регулярные встречи уже есть в компании?
- Какие из них будут обслуживать ран, какие — нет?
- Нужно ли добавить ран-специфичные встречи (стендапы, ретро, чекпоинты по стадиям)?

### 2. Каналы коммуникации

- Где обсуждаются операционные вопросы (чат, канал, email, Notion)?
- Где принимаются решения и фиксируются?
- Кто модерирует / ведёт документацию?

### 3. Принятие решений

- Кто принимает финальное решение на каждой стадии (Founder? Голосование? Конкретный ролевик)?
- Как эскалируются разногласия?
- Что происходит, если Founder и Producer спорят?

### 4. Конфликты

- Были ли недавно конфликты в команде? Чем закончились?
- Есть ли скрытые недовольства (из 04-team-interviews)?
- Кто модерирует, если возникает новый конфликт?

### 5. Контрольные точки пайплайна

На каждую стадию 1-8 назначить checkpoint-встречу:
- Участники (из ролевой модели)
- Повестка (что должно быть готово к встрече)
- Решение (go / no-go / pivot)

## Выход

- Файл `results/communication-system.md`:
  - Ритуалы (регулярные и ран-специфичные)
  - Каналы
  - Принятие решений
  - Модерация конфликтов
  - План checkpoint-встреч по стадиям
