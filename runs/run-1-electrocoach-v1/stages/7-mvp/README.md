# Stage 7 — MVP

## Цель

Собрать минимальный работающий артефакт, через который гипотеза проверяется действием (не только кликами). Формат зависит от рана: бот, веб-приложение, сервис-пилот, консалтинговый пакет.

## Inputs

- PRD из Stage 4
- Core Jobs из Stage 2
- Поток из лендингов (Stage 6) → куда уходит пользователь

## Prompts

- `mvp.md` — скелет MVP-плана: scope, стек, сроки (перенесено из Run 1)
- `ajtbd-graph-of-work.md` — граф работ, на которые MVP реагирует (перенесено из Run 2)

## Outputs

- Код артефакта: либо внутри `results/`, либо external (в `meta.yml` указать `mvp_artifact.path`)
- `results/spec/` — если используется spec-kit методология (constitution → spec → plan → tasks)
- `results/deploy.md` — как деплоится, где живёт

## Methodology

## Note

Живые артефакты предыдущих ранов могут жить вне этой папки по CI-контракту (пример: `/bot/` — это MVP Run 1, `.github/workflows/bot.yml` триггерится на `bot/**`). Новый ран с аналогичным артефактом — кладёт код **внутрь** `runs/<run>/stages/7-mvp/` и заводит собственный workflow.
