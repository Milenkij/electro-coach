# B2B-ветка ElectroCoach — результаты работы

Это рабочая папка для B2B-продукта **«Второй взгляд» + квартальный контракт**. Независимая ветка от B2C-направления (см. [CLAUDE.md](/CLAUDE.md) в корне проекта).

**Для следующего агента:** начни с чтения этого README → потом [ajtbd-analysis.md](ajtbd-analysis.md) → потом [PLAN.md](PLAN.md).

---

## Продукт в одной фразе

Внешнее зрение для фаундера в плато: за 3 дня увидеть, что тормозит компанию (стадия / фаундер / команда / рынок) и где один рычаг; дальше — квартальный контракт с ежемесячным циклом.

---

## Ключевые факты

| Параметр | Значение |
|---|---|
| **Сегмент** | Фаундер/CEO, компания 50–300 человек, выручка **1 млрд+ ₽/год**, 3–7 лет, рост 2–3 квартала на плато |
| **Точка входа** | «Второй взгляд» — 3 дня, 150 000 ₽, засчитывается в первый месяц контракта |
| **Основной SKU** | Квартальный контракт — 300–500 000 ₽/мес |
| **Big Job** | Вернуть компанию на траекторию роста, управлять ситуацией, а не реагировать |
| **Core Job (целый продукт)** | Иметь рядом партнёра, который ежемесячно проверяет 4 слоя и показывает рычаг, без найма штатного CoS / HRD / strategy advisor |
| **Две работы, где мы заменяем всех** | W6 «понять, где рычаг» (это продаёт «Второй взгляд») и W10 «регулярный цикл корректировки» (это продаёт контракт) |

## Ключевые решения (decisions log)

### Сегмент и позиционирование
- **Выручка сегмента — 1 млрд+ ₽/год, не 100М+.** Проверено пользователем. Все тексты обновлены.
- **Сегмент объединяет бизнес-работу (вернуть рост) и личную работу ЛПР (сохранить статус лидера).** Без личной работы ЛПР B2B-продажа не летает.
- **Старые 5 EAP-сегментов (HR Enterprise, L&D, CEO SMB, Transformation, IT Remote) — legacy.** Лендинги остались в `site-b2b/` справочно. Новые продажи не идут на эти сегменты.

### Продуктовая модель
- **Продукт = 4 слоя + рычаг,** не 3 слоя. Добавлены «стадия бизнеса» (Adizes) и «состояние фаундера». Четырёхслойная диагностика отличает продукт от всех конкурентов, которые работают по одному слою.
- **Core Job на весь продукт одна.** Продукт не разваливается на «отдельную диагностику» + «отдельный коучинг» + «отдельный HR-сервис» — это защищает цельность.
- **Big Job не выполняется продуктом полностью.** Мы закрываем шаг «понять, где рычаг» (W6) и «регулярно корректировать» (W10).

### Деливери
- **Deliverable — 1-page A3 canvas + запись разговора Day 3.** НЕ 15 слайдов. 15-страничный отчёт противоречит ценностям клиента V6.4 («сказать в 3 предложениях») и V6.8 («не PDF на полке»).
- **Adizes — основной нарратив стадии.** Greiner и Scaling Up — внутренняя библиотека ограничений в промпте, не отдельные артефакты.
- **Maslach Burnout Inventory срезан.** Ценность V6.1 (founder state) создаётся через интервью + мини-360; Maslach дублирует без нового сигнала.
- **Porter 5 Forces срезан как артефакт.** Остался как чек-лист внутри market research promt.
- **Per-person-карточки (1 стр. на каждого из 10–20 ключевых) срезаны.** Сводка + 3–5 highlight-ситуаций.

### Что добавили (закрывали ценность)
- **«3 Sentences Check» в Delivery Script** — V6.4 (фаундер должен уметь отстоять рычаг).
- **Founder Kickoff Briefing + Pulse Privacy Note + Thank-you Note** — V6.9 (команда почувствовала, что её слушают, без разглашения результатов).

### Цена
- **150K засчитывается в первый месяц контракта** — «фактически бесплатно» для тех, кто продолжает.
- **300–500K/мес — в зоне операционного решения фаундера на 1 млрд+,** не вопрос для совета. Это критично для W5 (политическая цена решения).

## Принципы работы для следующего агента

1. **AJTBD-файлы — источник истины.** При конфликте с дореверсными — обновляй дореверсные.
2. **Трассируй от ценности.** Прежде чем добавить артефакт/задачу — проверь, какую ценность V5.x / V6.x она порождает. Если не порождает — не добавляй.
3. **Не добавляй методологию ради методологии.** Каждая рамка (Adizes, Hersey-Blanchard, и т.д.) должна давать новый сигнал; если дублирует имеющуюся — срезай.
4. **Deliverable — краткий + живой.** Избегай многослайдных отчётов; то, что не помещается в 1-page canvas + разговор, ложится «на полку».
5. **Изменения в B2B не переносятся автоматически в B2C.** Работаешь в `2-3-MVP B2B/` — остаёшься в этой ветке (см. [CLAUDE.md](/CLAUDE.md)).
6. **Согласуй с владельцем продукта.** Пользователь — владелец требований. Вопросы из [PLAN.md](PLAN.md) (открытые) — не додумывай, спрашивай.
7. **AJTBD-промпты:** используй [../prompts/](../prompts/) — `ajtbd-graph-of-work.md`, `ajtbd-landing.md`, `ajtbd-rat.md`, `ajtbd-segments-b2b.md`.
