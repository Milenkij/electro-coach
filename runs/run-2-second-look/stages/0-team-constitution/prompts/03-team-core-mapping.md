# 03 — Ядро команды и ролевая модель

Зафиксировать команду, которая заряжается в ран, в виде ролевой модели. Что должно быть закрыто, кем закрыто, где пробелы.

## Вход

- Выполнены `01-founder-interview.md` для всех фаундеров-участников
- Есть понимание, кто ещё может участвовать (сотрудники, внешние эксперты, подрядчики)

## Работа

### 1. Перечислить всех участников рана

| Участник | Роль в компании | Роль в ране | % времени / неделю |
|---|---|---|---|
| … | … | … | … |

### 2. Собрать минимальную ролевую модель рана

Для пайплайна v1 минимум (могут совмещаться одним человеком):

- **Founder / Product Owner** — держит гипотезу, принимает решения о pivot
- **Producer / Pipeline Runner** — держит раму и темп, следит за переходом между стадиями
- **Researcher** — отвечает за Stage 2 (segmentation) и Stage 3 (market-research)
- **Product Designer / UX** — отвечает за Stage 4 (PRD) и Stage 6 (landings)
- **Brand / Naming** — отвечает за Stage 5 (naming-brand)
- **Engineer / Builder** — отвечает за Stage 7 (MVP)
- **Analyst** — отвечает за Stage 8 (analytics)

### 3. Сопоставить участников с ролевой моделью

- Какие роли закрыты конкретными людьми?
- Какие роли **не закрыты** (либо пусто, либо фаундер совмещает с Product Owner → перегруз)?
- Какие роли нужны временно (только на одну-две стадии) — можно закрыть подрядчиком?

### 4. Для dyad-ранов (2 фаундера без сотрудников)

- Распределить роли между двумя фаундерами честно (не «всё на одного»)
- Явно отметить роли, которые **придётся временно совмещать**, и следить за этим

### 5. Решение

- Если не закрыты критические роли (Producer или Founder) → стоп, собирать команду дальше
- Если не закрыты вспомогательные роли → идём, но с отметкой «привлекаем подрядчика на Stage X»

## Выход

- Файл `results/team-core-mapping.md`:
  - Таблица участников
  - Ролевая модель с галочками «закрыто / пусто / совмещено»
  - Решение: едем / не едем / едем с подрядчиком на Stage X
