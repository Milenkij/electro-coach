# Pipeline Template v1

Шаблон пайплайна производства цифрового продукта. При старте нового рана копируется целиком в `runs/run-<N>-<name>/` и становится частью рана. Ран замораживается на своей версии шаблона — delta-изменения дают следующую версию (v2, v3…), но не мутируют уже стартовавшие раны.

## Governing methodology: Метод параноика

Пайплайн построен вокруг принципа **контроля неопределённости** из «Метода параноика»: неопределённость по ходу работ должна схлопываться быстрее, чем расходуются ресурсы. Каждая стадия — шаг воронки неопределённости: фиксирует некоторое знание/артефакт и сужает пространство решений для следующих стадий.

Пять принципов, которые пронизывают все стадии:

1. **Проектирование** — любая работа начинается с описания желаемого результата (артефакта стадии), а не с действий.
2. **Гибкие проектные команды** — каждый ран имеет свою команду (Stage 0), не живёт на общем backlog.
3. **Продюсирование** — в ране есть роль продюсера (держит раму и темп), даже если она совмещена с founder.
4. **Сериал, а не фильм** — работа режется на этапы с чекпоинтами, не на монолит.
5. **Вовлечённость бизнеса** — заказчик (founder) не «принимает» результат в конце, а участвует в каждом чекпоинте.

## Stage 0 gating

Ран не считается активным в Stage 1, пока в `stages/0-team-constitution/results/constitution.md` не лежит подписанный артефакт. Исключение — исторические раны (v0), прошедшие до введения Stage 0: в их `stages/0-team-constitution/results/` кладётся `STUB.md` с пометкой «historical gap», `meta.yml` → `stage_0_status: historical-gap`.

## Template vs Run

- **Этот шаблон (`pipeline-templates/v1/`) — read-only** после вмерзания в версию. Менять нельзя, можно только создать v2.
- **Ран (`runs/run-N-name/`) — рабочее пространство.** Все артефакты пишутся в `runs/.../stages/<n>/results/`.
- Промпты в `stages/<n>/prompts/` — «каноны»: их можно читать и запускать, но не редактировать внутри рана. Поправка промпта = вклад в следующую версию шаблона.
