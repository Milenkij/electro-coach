# Naming Playbook

Пошаговый процесс разработки названия продукта. Основан на методологиях Lexicon Branding (Diamond Framework), Landor (8 Principles of Naming) и таксономии How Brands Are Built.

Плейбук рассчитан на многократное использование. Каждый запуск (run) создаёт папку `naming/runs/YYYY-MM-DD-<slug>/` с артефактами по каждому шагу.

---

## Структура файлов

```
naming/
├── PLAYBOOK.md              ← этот файл
└── runs/
    └── YYYY-MM-DD-<slug>/   ← папка конкретного запуска
        ├── 01-brief.md
        ├── 02-territories.md
        ├── 03-longlist.md
        ├── 04-shortlist.md
        ├── 05-evaluation.md
        └── 06-finalists.md
```

---

## Перед стартом

**Инструкция для агента:**
- Каждый шаг фиксируется отдельным MD-файлом в папке текущего run.
- Файл создаётся сразу по завершении шага, а не в конце процесса.
- Переход к следующему шагу — только после явного подтверждения пользователя.
- Не додумывай за пользователя. Задавай вопросы, фиксируй ответы дословно.
- Если пользователь хочет вернуться к предыдущему шагу — обнови соответствующий файл и отметь, что изменилось.

## Шаг 1. Бриф (Diamond Framework)

**Файл:** `01-brief.md`

**Задача:** Зафиксировать, что имя должно делать для бренда. Определить границы поиска до того, как начнётся генерация.

**Формат:** Агент задаёт вопросы по блокам ниже. Пользователь отвечает. Агент фиксирует ответы в файле.

### Блок A. Продукт и аудитория

| # | Вопрос | Зачем |
|---|--------|-------|
| A1 | Опиши продукт одним предложением. Что он делает? | Ядро позиционирования |
| A2 | Кто основная аудитория? Демография, контекст, уровень дохода | Понимание, на чьём языке говорить |
| A3 | В какой момент жизни/работы человек приходит к продукту? | Эмоциональный контекст первого контакта |
| A4 | Какие альтернативы есть у аудитории сейчас? Как они их называют? | Конкурентное поле имён |

### Блок B. Diamond Framework (Lexicon)

| # | Вопрос | Зачем |
|---|--------|-------|
| B1 | Что значит "победить" для имени? Как выглядит идеальный результат через год? | Верхняя точка ромба — определяет амбицию |
| B2 | Что у нас уже есть? Какие ассоциации, истории, метафоры уже работают? | Правая точка — активы, от которых можно оттолкнуться |
| B3 | Чего не хватает? Что имя должно добавить, чего пока нет? | Нижняя точка — дефициты |
| B4 | Что имя должно сообщать при первом контакте? Одна мысль | Левая точка — ключевое сообщение |

### Блок C. Ограничения и предпочтения

| # | Вопрос | Зачем |
|---|--------|-------|
| C1 | Какой тон: серьёзный / дружелюбный / дерзкий / нейтральный? | Эмоциональный фильтр |
| C2 | Русское слово, иностранное, выдуманное — что допустимо? | Лингвистические границы |
| C3 | Есть ли слова или ассоциации, которые точно НЕ подходят? | Чёрный список |
| C4 | Где будет жить имя? Telegram-бот, домен, приложение, лендинг, всё сразу? | Технические ограничения (длина, символы) |
| C5 | Имя должно работать только на русском или на международном рынке тоже? | Географические границы |

### Блок D. Масштаб

| # | Вопрос | Зачем |
|---|--------|-------|
| D1 | Это имя для одного продукта или зонтичный бренд? | Ширина покрытия |
| D2 | Какие продукты/услуги могут появиться через 2–3 года под этим именем? | Тест на потолок |

**Критерии завершения шага:**
- [ ] Все вопросы A1–D2 имеют ответы (или явно отмечены как "не актуально")
- [ ] Пользователь подтвердил: "Бриф верный, идём дальше"
- [ ] Файл `01-brief.md` создан и сохранён

## Шаг 2. Территории

**Файл:** `02-territories.md`

**Задача:** Определить 5–8 смысловых территорий — метафорических пространств, из которых будем черпать имена. Территория — не слово и не название. Это направление поиска.

**Формат:** Агент предлагает территории на основе брифа. Пользователь добавляет свои, убирает лишние, приоритизирует.

### Как определить территорию

Территория описывается:
- **Название** — 2–3 слова (напр. "Античная мудрость")
- **Метафора** — какую идею несёт (напр. "знание, проверенное тысячелетиями")
- **Примеры слов** — 5–10 слов для иллюстрации, НЕ как финальные варианты
- **Тип имени** — описательное / суггестивное / абстрактное
- **Релевантность брифу** — какие пункты брифа закрывает

### Рекомендации

- Территории должны быть **разнородными**. Если 3 из 5 — про античность, это одна территория, не три.
- Включи минимум одну "странную" территорию — ту, которая кажется нерелевантной (метод Lexicon: команда, которая думает, что называет велосипед).
- Не оценивай территории на этом этапе. Оценка — на шаге 4.

**Критерии завершения шага:**
- [ ] Определены 5–8 территорий в формате выше
- [ ] Минимум одна территория предложена пользователем
- [ ] Пользователь подтвердил список территорий
- [ ] Файл `02-territories.md` создан и сохранён

## Шаг 3. Генерация (лонглист)

**Файл:** `03-longlist.md`

**Задача:** Сгенерировать максимальное количество имён-кандидатов. Без оценки, без фильтра.

**Формат:** Агент генерирует по 30–50 имён на каждую территорию. Пользователь добавляет свои ассоциации. Всё записывается в файл.

### Правила генерации (метод Lexicon)

1. **Никакой оценки во время генерации.** Записывай всё, даже абсурдное.
2. **Цель: 300+ кандидатов.** Из 300 выживут 30. Из 30 — 3.
3. **Разные конструкции:** реальные слова, составные, изобретённые, аббревиатуры, имена собственные.
4. **Разные языки:** русский, латынь, греческий, английский — если бриф допускает.
5. **Фиксируй территорию** рядом с каждым словом — пригодится при фильтрации.

### Структура файла

```markdown
## Территория 1: [название]

1. слово_1
2. слово_2
...

## Территория 2: [название]

1. слово_1
...

## Слова от пользователя (вне территорий)

1. ...
```

**Критерии завершения шага:**
- [ ] Минимум 200 кандидатов (в сумме по всем территориям)
- [ ] Каждая территория представлена минимум 20 кандидатами
- [ ] Пользователь добавил свои варианты (или явно сказал "у меня нет")
- [ ] Файл `03-longlist.md` создан и сохранён

## Шаг 4. Грубый фильтр (шортлист)

**Файл:** `04-shortlist.md`

**Задача:** Сократить лонглист до 30–50 кандидатов, отсеяв явно непроходные.

**Формат:** Агент прогоняет каждого кандидата через чеклист. Результат — таблица "прошёл / не прошёл" с причиной отсева.

### Чеклист отсечения

Кандидат вылетает, если не проходит **любой** из критериев:

| # | Критерий | Как проверить |
|---|----------|--------------|
| F1 | **Произносимость.** Можно сказать вслух без запинки? | Прочитай вслух 3 раза подряд |
| F2 | **Длина.** ≤ 4 слога, ≤ 12 букв | Посчитай |
| F3 | **Негативные ассоциации.** Нет ли мата, оскорблений, двусмысленностей на русском и английском? | Подумай на 2 языках |
| F4 | **Уникальность в поиске.** Первая страница Google не забита чужими продуктами? | Быстрый поиск |
| F5 | **Telegram-юзернейм.** Можно собрать читаемый @username? | Проверь формат |
| F6 | **Не пересекается с чёрным списком из брифа (C3)** | Сверься с брифом |

### Структура файла

```markdown
## Прошли фильтр (N шт.)

| # | Название | Территория | Комментарий |
|---|----------|-----------|-------------|
| 1 | ...      | ...       | ...         |

## Не прошли фильтр (основные причины)

| Причина | Кол-во отсеянных | Примеры |
|---------|-----------------|---------|
| F1 — непроизносимо | 42 | ... |
| F3 — негативные ассоциации | 15 | ... |
```

**Критерии завершения шага:**
- [ ] Каждый кандидат из лонглиста проверен по F1–F6
- [ ] Шортлист содержит 30–50 кандидатов
- [ ] Если меньше 30 — вернуться к шагу 3 и догенерировать
- [ ] Пользователь просмотрел шортлист, убрал те, что не нравятся интуитивно
- [ ] Файл `04-shortlist.md` создан и сохранён

## Шаг 5. Глубокая оценка

**Файл:** `05-evaluation.md`

**Задача:** Оценить оставшихся кандидатов по единой системе критериев, привязанной к брифу. Сократить до 5–7 финалистов.

**Формат:** Матрица оценки. Каждый кандидат — строка. Каждый критерий — столбец. Оценка 1–10.

### Матрица критериев

Базовый набор (адаптировать под бриф на шаге 1):

| Критерий | Что оцениваем | Вес |
|----------|--------------|-----|
| **Сообщение** | Передаёт ли ключевую мысль из B4 брифа? | x2 |
| **Тон** | Совпадает ли с тоном из C1? | x2 |
| **Запоминаемость** | Вспомнишь ли через час? (Landor #1) | x2 |
| **История** | Есть ли за именем нарратив для лендинга? (Landor #2) | x1 |
| **Звучание** | Приятно ли произносить вслух? (Landor #3) | x1 |
| **Отстройка** | Отличается ли от конкурентов из A4? (Landor #6) | x1 |
| **Масштаб** | Не тесно ли через 2–3 года? (D2) | x1 |
| **Word-of-mouth** | Как звучит "Я пользуюсь [X]" / "Попробуй [X]"? | x1 |

### Дополнительные тесты (качественные, без баллов)

Для каждого кандидата из топ-10 по баллам:

1. **Тест "скажи другу"** — напиши 3 фразы, которые реальный пользователь скажет, рекомендуя продукт. Звучит естественно?
2. **Тест "заголовок лендинга"** — напиши hero-заголовок с этим именем. Работает?
3. **Тест "через 3 года"** — представь, что продукт вырос. Имя всё ещё подходит?
4. **Тест "худший контекст"** — в каком контексте имя звучит хуже всего? Насколько это критично?

### Структура файла

```markdown
## Матрица оценки

| # | Название | Сообщение (x2) | Тон (x2) | Запомин. (x2) | История | Звучание | Отстройка | Масштаб | WoM | ИТОГО |
|---|----------|---------------|----------|--------------|---------|----------|-----------|---------|-----|-------|
| 1 | ...      | .../10        | .../10   | .../10       | .../10  | .../10   | .../10    | .../10  | .../10 | ... |

## Качественные тесты (топ-10)

### [Название 1]
- Скажи другу: ...
- Заголовок: ...
- Через 3 года: ...
- Худший контекст: ...
```

**Критерии завершения шага:**
- [ ] Все кандидаты из шортлиста оценены по матрице
- [ ] Топ-10 прошли качественные тесты
- [ ] Пользователь выбрал 5–7 финалистов
- [ ] Файл `05-evaluation.md` создан и сохранён

## Шаг 6. Стресс-тест финалистов

**Файл:** `06-finalists.md`

**Задача:** Проверить 3–5 финалистов на реальную пригодность. Принять решение.

**Формат:** Каждый финалист проходит полный набор проверок.

### Проверки

| # | Проверка | Как выполнить | Блокирующая? |
|---|----------|--------------|-------------|
| S1 | **Домен** | Проверить доступность .ru, .com, .ai | Да |
| S2 | **Telegram** | Проверить @username | Да |
| S3 | **Соцсети** | Instagram, VK, YouTube — занято ли? | Нет |
| S4 | **Товарный знак** | Поиск по базе ФИПС (класс 42, 35) | Да |
| S5 | **Google / Yandex** | Что на первой странице выдачи? | Нет |
| S6 | **Визуал** | Как выглядит в логотипе? (текстовый мокап) | Нет |
| S7 | **Мокап лендинга** | Hero-секция с названием — работает? | Нет |
| S8 | **Опрос** | Показать 3–5 представителям ЦА, собрать реакцию | Нет |

### Структура файла

```markdown
## Финалист 1: [Название]

### Проверки
| Проверка | Результат | Статус |
|----------|----------|--------|
| S1 Домен | .ru — свободен, .com — занят | WARN |
| S2 Telegram | @name_bot — свободен | OK |
| ... | ... | ... |

### Мокап заголовка
> [Название] — [слоган из одного предложения]

### Вердикт
[Проходит / Не проходит / Проходит с оговорками]

---

## Финалист 2: [Название]
...

---

## Итоговое решение

**Выбрано:** [Название]
**Причина:** ...
**Следующий шаг:** ...
```

**Критерии завершения шага:**
- [ ] Все финалисты прошли проверки S1–S5 (минимум)
- [ ] Блокирующие проверки (S1, S2, S4) пройдены хотя бы одним кандидатом
- [ ] Пользователь принял решение
- [ ] Файл `06-finalists.md` создан и сохранён

## Приложение A. 8 принципов Landor (справочник)

Используй как чеклист на шагах 3–5.

1. **Запоминаемость.** Имя застревает в голове с первого раза?
2. **Смысл.** За именем есть история, которую хочется рассказать?
3. **Звучание.** Произнеси вслух. Приятно? Энергично? Или вязко?
4. **Не жди любви с первого взгляда.** Хорошие имена растут. Google казался странным.
5. **Слушай страх.** Если имя пугает — возможно, оно достаточно смелое.
6. **Выделяйся.** Если конкуренты — "SmartCoach", "AI Mentor", "MyHelper" — не будь как они.
7. **Генерируй больше.** 100 — мало. 300 — нормально. 1000 — как Lexicon.
8. **Имя эластично.** Ты натянешь на него нужный смысл. Amazon начинался с книг.

## Приложение B. Типология имён (справочник)

| | Реальное слово | Составное | Изобретённое |
|---|---------------|-----------|-------------|
| **Описательное** | Booking.com | YouTube | — |
| **Суггестивное** | Slack, Amazon | Pinterest, BlackBerry | Febreze |
| **Абстрактное** | Apple, Uber | — | Kodak, Xerox, Sonos |

Используй для разнообразия на шаге 3: проверяй, что лонглист покрывает минимум 4 из 6 ячеек.
