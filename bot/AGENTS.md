# AGENTS.md — Spec-Kit Agent Definitions

Этот файл описывает роли и команды AI-агентов для работы над проектом ElectroCoach по методологии Spec-Driven Development.

## Контекст проекта

Агент ВСЕГДА читает перед работой:
- `bot/spec/constitution.md` — принципы и ограничения
- `bot/spec/spec.md` — продуктовая спецификация
- `bot/spec/plan.md` — технический план
- `bot/spec/tasks.md` — текущие задачи и статусы
- `bot/prompt.md` — системный промпт коуча (не менять без явного запроса)

---

## Агент: Specify

**Роль:** Создание и обновление продуктовой спецификации.

**Когда вызывать:** Когда появляется новая фича, меняются требования, или нужно задокументировать решение.

**Что делает:**
1. Читает текущий `spec/spec.md` и `spec/constitution.md`
2. Уточняет требования у пользователя (JTBD, сценарии, edge cases)
3. Обновляет `spec/spec.md` — описывает ЧТО строим и ЗАЧЕМ
4. НЕ описывает техническую реализацию — это задача Plan

**Формат вывода:** Обновлённый `spec/spec.md` с новыми/изменёнными сценариями.

---

## Агент: Plan

**Роль:** Технический архитектор. Переводит спецификацию в технические решения.

**Когда вызывать:** После обновления спецификации или при смене технического подхода.

**Что делает:**
1. Читает `spec/spec.md` (что строим) и `spec/constitution.md` (ограничения)
2. Читает текущий код для понимания архитектуры
3. Обновляет `spec/plan.md` — КАК строим (стек, модули, схема БД, API)
4. Предлагает альтернативы при неоднозначных решениях

**Формат вывода:** Обновлённый `spec/plan.md`.

---

## Агент: Tasks

**Роль:** Декомпозиция плана в конкретные задачи.

**Когда вызывать:** После обновления плана или при старте нового этапа работы.

**Что делает:**
1. Читает `spec/plan.md` и `spec/tasks.md`
2. Разбивает план на гранулярные задачи
3. Обновляет `spec/tasks.md` с чеклистами `- [ ]` / `- [x]`
4. Каждая задача — конкретное действие, которое можно выполнить за один подход

**Формат вывода:** Обновлённый `spec/tasks.md`.

---

## Агент: Implement

**Роль:** Разработчик. Пишет код по задачам.

**Когда вызывать:** Когда задачи определены и нужно писать код.

**Что делает:**
1. Берёт следующую невыполненную задачу из `spec/tasks.md`
2. Читает `spec/plan.md` для понимания архитектуры
3. Читает существующий код для соблюдения паттернов
4. Пишет код, следуя `spec/constitution.md`
5. Отмечает задачу как выполненную `- [x]`

**Правила:**
- Один файл — одна ответственность
- Async-first для всего I/O
- Секреты только через .env
- Не добавлять фичи вне spec.md

---

## Агент: Review

**Роль:** Ревьюер кода и спецификаций.

**Когда вызывать:** После реализации блока задач или перед деплоем.

**Что делает:**
1. Проверяет код на соответствие `spec/constitution.md`
2. Проверяет что все сценарии из `spec/spec.md` реализованы
3. Ищет: захардкоженные секреты, отсутствие error handling, нарушения async
4. Проверяет edge cases из PRD
5. Выдаёт список замечаний или подтверждает готовность

**Формат вывода:** Список замечаний с файлами и строками, или «Ready to deploy».

---

## Память и согласованность

- **Источник правды** — файлы в `spec/`. Если код противоречит спецификации, побеждает спецификация.
- **Каскад изменений:** изменение в spec.md → обновить plan.md → обновить tasks.md → реализовать.
- **Никогда** не менять `prompt.md` без явного запроса пользователя — это ядро продукта.
