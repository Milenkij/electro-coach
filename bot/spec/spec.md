# Spec: ElectroCoach Telegram Bot MVP

## Что строим

Telegram-бот, который ведёт коуч-сессию по методологии GROW + Логические уровни Дилтса. Пользователь приходит с запросом → AI ведёт структурированный диалог → пользователь уходит с конкретным первым шагом.

## Целевой пользователь

Фаундер в стагнации. Предприниматель 5–100М выручки, 3–7 лет в бизнесе, принимает решения один.

## Ключевые сценарии

### Сценарий 1: Первая сессия
1. Пользователь находит бота и отправляет `/start`
2. Бот приветствует и объясняет формат (1 сессия = 1 запрос → диалог → первый шаг)
3. Пользователь пишет свой запрос
4. AI ведёт диалог по GROW + Дилтс (системный промпт из `prompts/`)
5. AI формулирует первый шаг
6. AI спрашивает: «Сессия завершена или остались вопросы?»
7. Пользователь завершает → бот запрашивает оценку 1–10
8. Пользователь ставит оценку → бот благодарит

### Сценарий 2: Исчерпаны бесплатные сессии
1. Пользователь пытается начать сессию
2. Бот сообщает, что бесплатные сессии закончились
3. Бот предлагает подписку (заглушка — ссылка/контакт)

### Сценарий 3: Активная сессия уже есть
1. Пользователь отправляет `/new` при активной сессии
2. Бот предлагает завершить текущую (`/stop`) или продолжить

## Команды бота

| Команда | Действие |
|---------|----------|
| `/start` | Приветствие + начало первой сессии |
| `/new` | Начать новую сессию |
| `/stop` | Завершить текущую сессию |

### Сценарий 4: Нетекстовое сообщение
1. Пользователь отправляет фото, голосовое, стикер, видео, документ или геолокацию
2. Бот отвечает, что пока работает только с текстом
3. Предлагает написать словами

**Почему:** Коуч-сессия — это диалог. MVP работает только с текстом. Молчание в ответ на нетекстовое сообщение выглядит как баг.

### Сценарий 5: Учёт токенов и стоимости
1. При каждом запросе к LLM бот сохраняет в БД (таблица `messages`, запись с ролью `assistant`):
   - `prompt_tokens` — кол-во токенов промпта
   - `completion_tokens` — кол-во токенов ответа
   - `cost` — стоимость запроса в USD (из поля `usage.cost` ответа OpenRouter)
2. Токены и стоимость по сессии / пользователю — агрегаты `SUM` по `messages`, отдельных колонок не дублируем
3. Полные тексты сообщений пользователя логируются в stdout для оперативной отладки

**Почему:** Нужен контроль расходов на LLM и возможность анализировать стоимость в разрезе сессий и пользователей.

### Сценарий 6: Стриминг ответа LLM
1. Пользователь отправляет сообщение в активной сессии
2. Бот сразу показывает draft «Думаю...» для мгновенной обратной связи
3. Бот запрашивает LLM через OpenRouter с `stream: true`
3. По мере получения чанков бот обновляет draft через `sendMessageDraft` (throttle ~300ms)
4. Пользователь видит текст в реальном времени (как в ChatGPT), сырой markdown
5. После завершения генерации бот отправляет финальное сообщение через `sendMessage` с HTML-форматированием — draft исчезает, сообщение остаётся в истории
6. Если стриминг упал — fallback на обычную отправку одним сообщением
7. Токены и cost парсятся из последнего чанка (`usage`) и сохраняются в БД

**Зависимости:** aiogram ≥ 3.24.0 (поддержка `sendMessageDraft`), OpenRouter SSE streaming.

### Сценарий 7: Тайминг сессии

**Цель:** Пользователь получает закрытый вопрос (ясность + конкретный первый шаг) в рамках заявленного времени. Управление временем — фоновое, незаметное для пользователя.

#### Флоу
1. Сессия начинается (`/start` или `/new`) → бот спрашивает "С чем пришёл сегодня?"
2. Пользователь описывает запрос
3. Коуч уточняет запрос (по GROW — этап Goal)
4. Когда запрос прояснён — коуч спрашивает: "Сколько у тебя есть времени на эту сессию?"
5. Пользователь отвечает в свободной форме ("минут 20", "полчаса", "час")
6. Коуч подтверждает и начинает работу, калибруя глубину под заявленное время

#### Передача времени в LLM
- При создании сессии фиксируется `started_at` (уже есть в БД)
- В **каждый** запрос к LLM добавляется системное сообщение с метаданными:
  ```
  [Метаданные сессии]
  Начало сессии: 2026-04-14 15:30 MSK
  Текущее время: 2026-04-14 15:47 MSK
  Заявленное время пользователя: 30 минут
  ```
- LLM сам решает, когда пора сворачивать к итогам — жёстких таймеров нет

#### Если время кончилось, а запрос расширяется
- Коуч мягко подсвечивает: "Кажется, это выходит за рамки тех 30 минут. Готов продолжить дольше, или зафиксируем то, что уже есть, и вернёмся в следующий раз?"
- Это поведение описывается в системном промпте, не в коде

#### Хранение
- Новое поле `time_budget TEXT` в таблице `sessions` — сырой ответ пользователя ("минут 20", "час")
- Заполняется один раз за сессию, после ответа на вопрос о времени

### Сценарий 8: Paywall (trial 72 часа)

**Цель:** Пользователь получает 72 часа бесплатного доступа с момента регистрации. После — CTA на оплату.

#### Модель доступа
- При создании пользователя: `subscription_until = NOW() + INTERVAL '72 hours'`
- Доступ есть, пока `NOW() < subscription_until`
- Старые поля `free_sessions_left` и `is_subscribed` — **удаляются**
- Ручное продление: `UPDATE users SET subscription_until = NOW() + INTERVAL '30 days' WHERE id = <user_id>`

#### Флоу при истёкшей подписке
1. Пользователь отправляет **любое** сообщение (текст, команду, что угодно)
2. Бот **всегда** отвечает (не молчит):
   ```
   Твой пробный период закончился.

   Чтобы продолжить работу с коучем, напиши @shapovalov_vsegda — обсудим подписку.
   ```
3. Бот не создаёт сессию, не отправляет в LLM — просто отвечает текстом с CTA

#### Миграция БД
```sql
ALTER TABLE users
  ADD COLUMN subscription_until TIMESTAMPTZ NOT NULL DEFAULT NOW() + INTERVAL '72 hours';

ALTER TABLE users
  DROP COLUMN free_sessions_left,
  DROP COLUMN is_subscribed;
```

#### Проверка доступа
- `db.py`: новая функция `is_subscription_active(user_id) -> bool` — `SELECT subscription_until > NOW()`
- `session.py`: `start_session()` проверяет подписку вместо `free_sessions_left`
- `session.py`: убирается `decrement_free_sessions()` из `_handle_rating()`
- `bot.py`: перед **любой** обработкой (команды, текст) — проверка подписки. Если истекла — CTA, return

## Ограничения MVP

- Только Telegram
- Только русский язык
- Нет памяти между сессиями
- Trial 72 часа, потом ручная подписка через @shapovalov_vsegda
