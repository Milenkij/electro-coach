# Spec: ElectroCoach Telegram Bot MVP

## Что строим

Telegram-бот, который ведёт коуч-сессию по методологии GROW + Логические уровни Дилтса. Пользователь приходит с запросом → AI ведёт структурированный диалог → пользователь уходит с конкретным первым шагом.

## Целевой пользователь

Фаундер в стагнации. Предприниматель 5–100М выручки, 3–7 лет в бизнесе, принимает решения один.

## Ключевые сценарии

### Сценарий 1: Первая сессия
1. Пользователь находит бота и отправляет `/start`
2. Бот приветствует и объясняет формат (1 сессия = 1 запрос → диалог → первый шаг)
3. Пользователь пишет свой запрос
4. AI ведёт диалог по GROW + Дилтс (системный промпт из `prompt.md`)
5. AI формулирует первый шаг
6. AI спрашивает: «Сессия завершена или остались вопросы?»
7. Пользователь завершает → бот запрашивает оценку 1–10
8. Пользователь ставит оценку → бот благодарит

### Сценарий 2: Исчерпаны бесплатные сессии
1. Пользователь пытается начать сессию
2. Бот сообщает, что бесплатные сессии закончились
3. Бот предлагает подписку (заглушка — ссылка/контакт)

### Сценарий 3: Активная сессия уже есть
1. Пользователь отправляет `/new` при активной сессии
2. Бот предлагает завершить текущую (`/stop`) или продолжить

## Команды бота

| Команда | Действие |
|---------|----------|
| `/start` | Приветствие + начало первой сессии |
| `/new` | Начать новую сессию |
| `/stop` | Завершить текущую сессию |

### Сценарий 4: Нетекстовое сообщение
1. Пользователь отправляет фото, голосовое, стикер, видео, документ или геолокацию
2. Бот отвечает, что пока работает только с текстом
3. Предлагает написать словами

**Почему:** Коуч-сессия — это диалог. MVP работает только с текстом. Молчание в ответ на нетекстовое сообщение выглядит как баг.

### Сценарий 5: Учёт токенов и стоимости
1. При каждом запросе к LLM бот сохраняет в БД (таблица `messages`, запись с ролью `assistant`):
   - `prompt_tokens` — кол-во токенов промпта
   - `completion_tokens` — кол-во токенов ответа
   - `cost` — стоимость запроса в USD (из поля `usage.cost` ответа OpenRouter)
2. Токены и стоимость по сессии / пользователю — агрегаты `SUM` по `messages`, отдельных колонок не дублируем
3. Полные тексты сообщений пользователя логируются в stdout для оперативной отладки

**Почему:** Нужен контроль расходов на LLM и возможность анализировать стоимость в разрезе сессий и пользователей.

### Сценарий 6: Стриминг ответа LLM
1. Пользователь отправляет сообщение в активной сессии
2. Бот сразу показывает draft «Думаю...» для мгновенной обратной связи
3. Бот запрашивает LLM через OpenRouter с `stream: true`
3. По мере получения чанков бот обновляет draft через `sendMessageDraft` (throttle ~300ms)
4. Пользователь видит текст в реальном времени (как в ChatGPT), сырой markdown
5. После завершения генерации бот отправляет финальное сообщение через `sendMessage` с HTML-форматированием — draft исчезает, сообщение остаётся в истории
6. Если стриминг упал — fallback на обычную отправку одним сообщением
7. Токены и cost парсятся из последнего чанка (`usage`) и сохраняются в БД

**Зависимости:** aiogram ≥ 3.24.0 (поддержка `sendMessageDraft`), OpenRouter SSE streaming.

## Ограничения MVP

- Только Telegram
- Только русский язык
- Нет памяти между сессиями
- Нет платёжной интеграции (заглушка)
- 2 бесплатные сессии на пользователя
